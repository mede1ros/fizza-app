# Fizza MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Fizza prototype into a reliable, offline, installable iPhone PWA (gastos fixos e variáveis + pizza por categoria), published on GitHub Pages.

**Architecture:** Pure business rules live in `src/domain/` (no React, fully unit-tested, all money in integer cents). `src/api/db.js` keeps the existing `db.entities.X.list/create/update/delete` interface but stores data in IndexedDB, runs a v1→v2 migration from localStorage, and exposes backup export/import. Pages consume the domain functions through TanStack Query; the shell is a HashRouter app with a bottom tab bar plus a side menu, built as a PWA by `vite-plugin-pwa` and deployed by GitHub Actions.

**Tech Stack:** React 18, Vite 6, Tailwind 3, shadcn/ui (Radix, `vaul` drawer), TanStack Query 5, Recharts 2, date-fns 3, `idb`, `vite-plugin-pwa`, Vitest + @testing-library/react + jsdom + `fake-indexeddb`.

**Spec:** `docs/superpowers/specs/2026-10-30-fizza-mvp-design.md`

## Global Constraints

- Target: Safari on iOS 16.4+, standalone mode. Must work in airplane mode after first open.
- URL `https://mede1ros.github.io/fizza-app/`. Vite `base: '/fizza-app/'`. Routing via `HashRouter`. Routes: `/`, `/gastos`, `/fixos`, `/metas`, `/compras`, `/config`, `/sobre`.
- All money stored as integer **cents** (`*_cents` fields). Formatting only at display time, `pt-BR` / `BRL`.
- Language pt-BR for all UI copy. No English strings left in UI.
- No external network resources at runtime (no CDN fonts or scripts).
- No real personal data in seeds, tests or fixtures.
- Money inputs use `inputmode="decimal"`. Touch targets ≥ 44px. Respect `env(safe-area-inset-*)`.
- Destructive actions use the shadcn `AlertDialog`, never `window.confirm`.
- Icon-only buttons have a pt-BR `aria-label`; every form field has a `<label>`.
- Default categories (name → color): Alimentação `#f59e0b`, Transporte `#3b82f6`, Moradia `#8b5cf6`, Saúde `#ef4444`, Educação `#06b6d4`, Lazer `#ec4899`, Assinaturas `#f97316`, Vestuário `#a78bfa`, Serviços `#84cc16`, Treino `#10b981`, Outros `#94a3b8`.
- Backup file name `fizza-backup-AAAA-MM-DD.json`. Backup reminder after 30 days. Version `1.0.0`.
- Commits authored by the repo's configured user; no tool attribution lines.

## Review Focus

1. **Due day 29–31 in short months (Feb, Apr…):** status and calendar treat it as the month's last day. Test in Task 3 (`effectiveDueDay`) and Task 8 (calendar render).
2. **Malformed, foreign or older-version backup:** import refuses with a message and leaves existing data untouched; an older `schema_version` is migrated. Tests in Task 4 and Task 5.
3. **Money typed the Brazilian way** (`"1.234,56"`, `"R$ 12"`, `" 12,5 "`, `"-3"`, `"abc"`, `""`): parsed correctly or rejected with a field error. Test in Task 2.
4. **Same category typed differently** (`"lazer"`, `"Lazer "`, `"LÁZER"` vs `"Lazer"`): merged into one pie slice with the canonical name and color. Test in Task 3.
5. **Year boundaries** (Dec→Jan navigation, installments crossing years, a fixed expense started in 2026-11 not counted in 2026-10): Tests in Task 2 (`addMonths`) and Task 3 (`isActiveInMonth`, `monthSummary`).

### Task 5: IndexedDB storage

**Files:**
- Modify (rewrite): `src/api/db.js`
- Create: `src/api/db.test.js`

**Interfaces:**
- Consumes: `STORES`, `SCHEMA_VERSION`, `migrateV1ToV2`, `DEFAULT_CATEGORIES`.
- Produces (same shape as today, plus new methods):
  - `db.entities.<Store>.list(sort?)`, `.create(data)`, `.update(id, data)`, `.delete(id)` for every name in `STORES`
  - `db.init() → Promise<void>`. Idempotent. It:
    1. opens the IndexedDB database `fizza`, version 1, with one object store per name in `STORES` plus `meta`;
    2. if `meta.schema_version` is missing and localStorage has any `fizza:*` key, copies the raw v1 JSON to `meta.v1_snapshot`, runs `migrateV1ToV2`, writes everything and then removes the `fizza:*` keys;
    3. if the database is empty, seeds `Category` with the defaults;
    4. sets `schema_version = 2`;
    5. calls `navigator.storage?.persist?.()`.
  - `db.exportAll() → data` (all stores)
  - `db.importAll(data)`: replaces all stores in a single transaction
  - `db.clearAll()`: clears the stores and re-seeds `Category`
  - `db.getMeta(key)`, `db.setMeta(key, value)` (`last_backup_at`)
